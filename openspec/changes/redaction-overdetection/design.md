# Design

## The measurement is the design

`meting-overdetectie-05` already says how to measure a list: detection runs once
per document and the outcomes differ only in what sits behind it, so the
difference is the list and nothing else. An effect across a reprocess comes from
`suppressed_by_list` in the run's own records, because a before/after across
runs compares two code versions. This change follows both rules and adds a new
measurement file next to the existing ones.

Before any entry or threshold is written, the baseline is recorded: precision,
recall and leaks per type, with and without lists, on the evaluation corpus. The
change is then made, and the same instrument is run again.

## What the corpus can and cannot show

LOCATION, ORGANIZATION, DATE_TIME and PHONE_NUMBER have no gold spans in the
corpus (meting 05), so every finding there counts as a false positive. The
absolute precision says little; only the difference between two runs on the same
detections does. Recall and leaks on seeded PII are the numbers that must not
move. A word like `juni` that the corpus does not seed cannot be shown to be
safe by the corpus alone, which is why the human read below stays.

## Allow list

A typed, anchored rule with a reason, as in `lists/allow.json`. Already guarded:
the CI check against the evaluation corpus, including the individual words of a
seeded value. Typed means typed: a word the detector types inconsistently needs
a rule under each type it is seen as, as `gemeente Gooise Meren` did and as
`bewoners` (PERSON only today) may.

## Score threshold

`detection_min_score` exists but only counts. A threshold that suppresses would
be a new behaviour: it removes detections below a score whatever the word is.
It is not rejected, but it is not decided either; the cost is that a low-scoring
real name disappears without a per-word review. If the measurement shows it, it
must show recall and leaks unchanged on the corpus, and Mark decides.

## Human gate

Candidate words come from the people who read the documents. The build side does
not open documents to look for more. The reason field in every allow entry is
how a reviewer sees the difference between an ordinary noun and an exempted
surname.

## Rejected alternatives

- **Pick the mechanism now.** The two have different risks; the numbers decide.
- **Frequency as the criterion.** Meting 04: a frequent value can be a real
  place name (`naarden`). Candidates are generated by counts, decided by a human.
- **Compare the index before and after a reprocess.** Meting 05: that compares
  two tool versions, not the list.
- **Let feedback update the list.** The anonymization spec says feedback is
  recorded, not auto-applied.
- **Mine the corpus for more words by reading it.** That is the human gate.
