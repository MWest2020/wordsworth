# Design: a pilot report template with empty gate slots

## Choices

- **A markdown template in `docs/`**, one file, headed by the parts in the
  proposal. The report is a copy of it. Proposed location:
  `docs/explanation/pilot-report-template.md` (open question in the proposal).
- **The check is copied from `check.json`, not re-described.** The report
  carries `checked_by`, `checked_at`, `robots_txt`, `anubis` and `decision`
  verbatim; `check.json` stays the source and the ingest gate
  (`document-lifecycle`) stays as it is.
- **The gate slots ship empty and are marked as Mark's.** The writer of the
  report (odin) leaves them empty. A report with an empty slot reports that
  gate as "not yet run", never as passed and never as failed.
- **The ranking slot carries two timestamps.** The time the questions were
  committed and the time of the first search. The order is the point: the
  existing rule is that the questions are written before any result is seen,
  and a timestamp pair is the only way to read that off afterwards.
- **The gates are the existing ones.** Ranking: expected document in the top 8
  for at least 4 of 5, for this pilot run only. PII: any residual direct
  identifier of a private person fails the pilot unless that document is
  excluded with the reason written down. This change restates them; it does
  not alter them.
- **The figures belong to the report, not the template.** The template has
  fields for document count, pages, pages without a text layer and scans; the
  values for this pilot are filled in by the report's writer.
- **"Recall" is banned in the whole template,** checked mechanically: the file
  does not contain the word. A narrower rule ("not for PII") would need a
  reader to judge each use; the template has no need for the word anywhere
  (the ranking gate is stated as "top 8", not as a metric name).
- **The findings are stated as findings, not requirements:** the unknown
  provenance of the 567-document dossier and the missing provenance on
  re-delivery. Neither is fixed here.

## Rejected

- **Enforcing "only Mark fills" in software** (a signature, a CODEOWNERS entry
  on the report, a check that fails when the slot was written by another
  author). More machinery than a one-off pilot report warrants, and
  `CODEOWNERS` is Mark's file to change. The template marks the slots; Mark
  is the reader who notices.
- **Letting the agent draft the questions or the PII read for Mark to
  approve.** A gate that the agent drafted and the person approved is no
  longer written before any result is seen.
- **Using "recall" with a qualifier** ("recall on the published material").
  The published material was redacted by the municipality, so there is
  nothing for the word to be measured against; any use invites the claim.
- **Putting the figures (12, 155, 2) into the template.** They would go stale
  with the next pilot.
- **A template generated by a script from `check.json` and the audit trail.**
  Worth considering for a second pilot; for the first, a script is built
  before the report has shown what it needs.

## Checks

No code runs, so the checks are on the file:

1. The template exists and has a heading for each of the six parts.
2. Both gate slots are present and empty (no question, no timestamp, no
   identifier filled in).
3. The ranking slot has fields for 5 questions with expected documents, the
   commit time and the first-search time.
4. The word "recall" does not occur in the template (case-insensitive).
5. `openspec validate pilot-report-template --strict` passes.
